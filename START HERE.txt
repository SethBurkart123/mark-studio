MARK STUDIO

macOS: open Mark Studio.app (Apple Silicon).
Windows: extract the complete ZIP, then run Mark Studio.exe. Keep its supporting folders beside it.
Linux: extract the tar.gz, then run ./mark-studio from the extracted directory. Requires a desktop with GTK / NSS and permission to open the USB serial device (commonly membership of dialout). Do not run as root or disable Chromium's sandbox.

1. Plug in USB, switch the machine on, and close ThorX6. Mark Studio auto-connects when exactly one compatible FTDI device is present.
2. Import SVG, PNG, JPG or WebP. Images are traced into outlines, not solid filled areas or centerlines. Use clean black-on-white line art for best results.
3. Enter the actual workpiece size and its offset from home. Fit, rotate, mirror or drag the artwork.
4. Clear the carriage path and click Home machine. Preview path runs with the marking pin inactive.
5. Check the placement, clamp the workpiece and set the tip gap. Click Engrave for one pass.

The red Stop button or Escape requests a software stop. The physical STOP button remains the emergency control. After a stop or disconnect, home again. Re-preview after changing artwork, placement, calibration or speed.

SVG text must be converted to paths. Expand clones and flatten clipping, masks, filters, and stylesheet-based SVGs in your vector editor before exporting. Unsupported constructs are rejected instead of silently changing the engraving.

This controller profile uses 140 x 80 mm conservative travel, 0.0069851349 mm/step and reversed X correction based on the tested machine. Verify travel and calibration for any other engraver in Machine settings. This is for the tested ThorX6-compatible XY dot-peen protocol, not GRBL, lasers or rotary machines. Depth is set physically with the strength knob and tip gap.

Save project preserves artwork and layout as a .peen file; Import reopens it. Everything stays offline.

VALIDATION
Mac UI and direct identification / position read were tested with a compatible FTDI controller. Windows and Linux packages are built but have not been run on those operating systems. macOS is locally signed, not Apple-notarized; Windows is unsigned.
